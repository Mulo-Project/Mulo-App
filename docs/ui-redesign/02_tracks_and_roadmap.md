# 02. Track 구분 · 로드맵 · 실행 순서

## Track A / Track B
| | Track A 페이지 레이아웃 | Track B 컴포넌트 외형 |
|---|---|---|
| 대상 | 섹션 순서, 컨트롤 묶음, sticky, 세로 공간, 시트 높이 | 크기 · 패딩 · 반경 · 색 역할 · 글자 · 아이콘 · 상태 표현 |
| 하지 않는 것 | 기능/진입 경로/반환값 제거 | 페이지 내 순서 변경, API · 콜백 변경, 기존 variant 삭제 |
| 승인 | 페이지별로 따로 | 컴포넌트(군)별로 따로 |
| 위험 | 해당 화면 한정 | 모든 호출처에 파급 (PillButton 47, AppTopBar 27 …) |
| 검증 | 640px 높이 · 큰 글자 · 키보드 · 선택 모드 | 8×2 테마, default/selected/pressed/focus/disabled/loading/error/destructive |

연결 규칙: 화면 After는 "현재 레이아웃 + 개선 컴포넌트"와 "레이아웃도 개선" 두 버전을 구분해 보여 준다. 어느 한쪽 승인이 다른 쪽 승인으로 해석되지 않는다.

## 페이지별 Track A 검토 후보 (비교만, 확정 아님)
- 홈: 현재 순서 유지 vs 최근 → 추천 → 많이 들은 곡 → 기록. 통계 높이 축소 여부.
- 보관함: 검색 + 정렬 한 줄/두 줄, 분류 탭 sticky 여부(640px), Hero 높이 축소, 선택 모드 혼잡도.
- 재생목록: YouTube 가져오기 버튼 강조도, 드래그 affordance, 빈 상태 진입.
- 재생목록 상세: 커버 헤더 높이/대표곡/다운로드 진행 세로 배분.
- 검색: 출처 선택 발견성, 정렬/결과 건수 위계. 미디어 상세: 하단 액션 위계. 다운로드 화면: 구역화(정보/색/저장/가사·자막), 키보드 시 하단 CTA.
- 플레이어/대기열/EQ: 3스타일 정체성 유지, 공통 조작부 일관성. 설정: 그룹 간격 · 위계(검색/목차는 신규 UI로 별도 표기).
- 셸: MiniPlayerBar와 DownloadBar 동시 표시 시 높이 · 터치 · 본문 하단 inset.

## 우선순위
**P0 (사용성 · 가독성 · 접근성, 가려지거나 오해되는 문제)**
1. 하단 겹침 점검: MiniPlayerBar + DownloadBar + 선택 바 + 목록 마지막 행 inset.
2. 테마 대비 감사 결과 중 실제 글자/아이콘이 3:1 · 4.5:1 미만인 조합(예상 후보: gold · ice · sunset 라이트).
3. 터치 영역 · 큰 글자 · 긴 한/영 문자열 잘림 (AppTopBar, TrackTile, SettingRow).
4. 다운로드 화면 키보드 가림, 시트/다이얼로그 SafeArea · 스크롤.

**P1 (일관성 · 위계, 반복되는 불균형)**
- 버튼 군(PillButton/CircleIconButton/PlainButton/RowIconButton) 위계와 상태 표현 통일.
- TrackTile 정보 밀도, 선택/다운로드 상태 variant.
- AppBottomNav 선택 표현(홈만 원형 강조 유지 vs 동등), AppTopBar large/detail 정렬.
- Dialog/Sheet/Menu 공통 외형(버튼 배치, 제목 위계, 높이).
- 보관함/검색/홈 Track A 대안 확정.

**P2 (마감)**: 미세 간격, 모션, 글로우 세기, 빈/로딩 상태 일러스트 톤, 설정 설명 문구 정돈.

## 실행 순서 (각각 별도 작업 단위 = 브랜치 1 + PR 1)
0. **기반 확인** (문서 PR): 실제 PC 캡처 확보 가능 시 `screenshots_test` 실행 결과 기록, route ↔ 화면 대조 보강. 캡처 불가면 건너뛰고 이후 단계는 "추정" 표기 유지.
1. **테마 감사**: 8×2 토큰 표 + 대비 계산 스크립트(테스트 코드로, 실제 resolve된 `AppPalette` 사용) + 권고안. 토큰 값 변경은 별도 승인.
2. **컴포넌트 감사 + 제안서**: 군별(버튼 → 행/목록 → 입력/선택 → 상단/하단 → 면/상태). 호출처 grep, 상태표, 영향 표.
3. **Dialog/Sheet/Menu/Overlay 감사**: 트리거 → UI → 선택 → 닫힘/반환값 → 후속 동작 표.
4. **Track A 페이지 제안**: 홈/보관함 → 재생목록 → 검색/상세/다운로드 → 플레이어/EQ → 설정/구독/가사.
5. **사용자 승인 후 구현**: 승인된 항목만, 컴포넌트 군 단위 PR(파급이 크므로 군 안에서는 쪼개지 않음), 이후 페이지 단위 PR.
6. 구현마다 worklog · decisions 기록, 회귀 확인(`flutter analyze`/`test`는 사용자가 PC에서).

각 제안 기록 항목: 현재 문제/근거(코드 위치) · 제안과 대안 · 참고 앱 · 보존 기능/API · 영향 페이지 · 접근성/테마 영향 · 난이도/회귀 위험 · 확신 수준(코드+캡처 / 코드만 / 검증 필요).
