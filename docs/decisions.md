## D-004 · 2026-09-29 · 테마는 교체 가능한 소스로
위젯은 색을 토큰에서만 읽고, 테마는 `ThemeSource`(기본 · 사용자 지정 · 곡 분위기)가 만든 팔레트로 바뀐다.
전환은 `ThemeExtension.lerp`로 애니메이션. 곡 분위기 · 사용자 지정 테마에서도 배경은 검정 유지, 강조 색은 배경 대비 7:1 이상으로 보정.
이유: 나중에 사용자 지정 · 곡 분위기 테마를 화면 수정 없이 붙이기 위해.

## D-014 · 2026-09-29 · 곡 · 재생목록 커버 이미지 등록
사용자 요청: 재생목록 · 음원에 맞는 이미지를 등록할 수 있게.

  보관함 DB(drift)를 붙일 때 고른 파일을 앱 폴더로 복사 · DB에 경로 저장으로 바꾼다.

- 유리 유지: 미니 플레이어 · 하단 탭(떠 있는 바), 원형 버튼 · tonal 버튼, 강조 카드(보관함 · 다운로드 요약, 검색 결과)
- 평범한 면으로: 설정 묶음 · 입력칸 · 선택 알약 · 스위치
- 재생목록 카드 · 플레이어 커버: `CoverCard` (사진, 없으면 테마 색 그라데이션, 유리 없음)

## D-017 · 2026-09-30 · 보관함 DB(drift) · 기기 음악 불러오기
- 앱 로컬 DB는 drift(SQLite, `drift_flutter`): `lib/core/database/app_database.dart`. 표: `tracks`(재생 주소 uri 유일), `covers`(키 → 앱 폴더로 복사한 이미지 경로).
- 보관함 화면은 가짜 데이터 대신 DB를 본다. 재생 대기열도 처음엔 비어 있다 (미니 플레이어 숨김).
- 기기 음악 불러오기(#11):
  - Android: 명세대로 MediaStore를 네이티브에서 조회 (`MediaStoreChannel.kt`, MethodChannel `music_app/media_store`). 권한은 `permission_handler`(13+ READ_MEDIA_AUDIO, 12 이하 READ_EXTERNAL_STORAGE).
  - 데스크톱: 폴더를 고르면 하위 폴더까지 음악 확장자 파일을 찾는다. 태그는 아직 안 읽고 파일 이름이 제목.
  - 같은 uri는 다시 넣지 않는다. 결과는 스낵바로 (n곡 추가 · 새 곡 없음 · 권한 필요 · 실패).
- 커버 이미지(D-014)는 이제 앱 지원 폴더 `covers/`로 복사 + DB 저장 → 다시 켜도 유지.
- `permission_handler` 13이 compileSdk 37을 요구해서 `android/app/build.gradle.kts`의 compileSdk를 37로.
- 라이트 모드 색 유리 카드는 옅게(`AppGlass.tintOpacityLight`) 칠하고 글자는 기본 글자색 (카드 안 글자색이 섞이던 문제 수정).

## D-023 · 2026-10-01 · 받기 팝업 · 장르 · 재생목록 저장
- 받기를 누르면 팝업(바텀시트)에서 제목 · 아티스트 · 장르와 **넣을 재생목록(여러 개)**을 정한 뒤 대기열에 넣는다. 재생목록은 팝업에서 바로 만들 수 있다.

## D-024 · 2026-10-01 · 앱 이름 Mulo · 패키지 com.mulo.app

- 요약은 DB에 저장하지 않고 조회 때 계산한다 (재생 기록 · 담긴 곡 · 곡 테이블 변경을 구독해 갱신). 곡은 재생 기록이 있는 것만 많이 들은 순 3개, 없으면 곡이 많은 아티스트 3명.

## D-026 · 2026-10-01 · 설정 보안 섹션 · 앱 잠금(PIN · 생체 인증)
- 설정에 **보안** 섹션을 만들고, 재생 섹션에 있던 "알림에 곡 정보 숨기기"를 옮겼다 (재생 섹션은 사라짐). 이 스위치는 아직 자리 표시.
- 앱 잠금: 4~6자리 숫자 PIN. 켜면 앱을 **새로 열 때**(콜드 스타트) 잠금 화면이 뜬다. 설정을 불러오기 전에도 내용을 가린다. 백그라운드에서 돌아올 때 다시 잠그는 것은 하지 않는다 (파일 선택 · 권한 창이 앱을 잠깐 가려도 잠기면 불편해서; 필요하면 다음 작업).
- PIN은 **솔트 + SHA-256 해시**만 `flutter_secure_storage`(Keystore)에 저장하고 PIN 자체는 저장하지 않는다. 켜짐 · 생체 사용 여부는 shared_preferences. 5번 연속 틀리면 30초 동안 입력을 막는다 (메모리 상태, 앱을 다시 열면 초기화).
- 생체 인증(지문 · 얼굴)은 `local_auth`, 선택 사항. 기기에 생체가 등록돼 있고 앱 잠금이 켜져 있을 때만 설정에 줄이 보이며, 켤 때 한 번 인증해 본인 확인을 한다. 생체는 PIN을 **대체**하는 풀기 수단일 뿐 PIN은 항상 남는다. 잠금을 끄면 PIN과 생체 설정을 함께 지운다.
- 잠금 **끄기 · PIN 바꾸기**는 본인 확인이 필요하다: 현재 PIN을 입력하거나, 생체 인증을 켜 둔 경우 등록된 지문 · 얼굴로 대신 확인한다 (화면을 열면 생체 인증을 한 번 묻고 키패드의 지문 버튼으로 다시 부를 수 있다). 앱을 쓰는 중이라도 켜 둔 채 자리를 비운 폰에서 잠금을 풀고 끄거나 PIN을 바꿀 수 있는 것을 막기 위해 확인을 유지한다.
- Android: `MainActivity`를 `FlutterFragmentActivity`로, `USE_BIOMETRIC` 권한 추가, `LaunchTheme` 부모를 `Theme.AppCompat.DayNight.NoActionBar`로 (local_auth 요구).
- 클린 아키텍처: `features/security` (`AppLockRepository` · `BiometricAuthenticator` 인터페이스, 유스케이스, `AppLockCubit`). 잠금 화면은 `MaterialApp.builder`에서 앱 위에 덮는 `LockGate`.

## D-027 · 2026-10-01 · 디버그 샘플 시드 · 다운로드 대기열 제어
- 보관함 · 재생목록 · 홈이 실제 DB가 된 뒤에도 화면을 샘플로 볼 수 있도록, **디버그 빌드에서만** 보관함이 비어 있을 때 샘플 곡 · 재생목록 · 재생 기록을 DB에 넣는다 (`core/sample/sample_seeder.dart`, main에서 `kDebugMode`). 곡이 이미 있으면 건드리지 않아 실제 데이터와 섞이지 않는다.
- 다운로드 대기열 저장소에 `pause` · `resume` · `cancel`을 추가했다. 이어받기는 항목을 대기로 되돌리고, 받는 곡이 없으면 대기 첫 곡이 이어서 받는다. 카드에 보일 곡은 받는 곡, 없으면 일시정지한 첫 곡.
- 받기 팝업의 재생목록은 스위치 나열 대신 별도 다중 선택 대화상자로 고른다 (목록이 길어져도 팝업이 늘어나지 않게).

## D-028 · 2026-10-01 · 불러오는 폴더 목록
- 불러올 폴더는 **기본 저장 위치 + 사용자가 더한 폴더**. 기본 저장 위치는 저장하지 않고 항상 맨 위에 더해 지우지 못하게 한다. 더한 폴더만 shared_preferences(`library.loadedFolders`)에 둔다.
- 스캔은 목록의 폴더(하위 폴더 포함)만 대상으로 한다 — 이전의 "기기 전체 음악 불러오기"와 달라진다. 폴더를 더하거나 빼면 바로 다시 스캔한다.
- 곡이 어느 폴더에서 왔는지는 `tracks.folder`(스키마 5)에 저장해 폴더별 곡 수를 센다 (Android는 MediaStore `DATA`의 상위 폴더). 폴더를 빼도 보관함의 곡은 지우지 않는다.
- 경로는 `/`로 맞추고 끝 구분자를 없애 비교한다 (`normalizeFolderPath`).

## D-029 · 2026-10-01 · 서버 주소는 빌드 때 `--dart-define`으로

- 서버 주소는 비밀값이 아니지만 저장소에 넣지 않고 빌드 명령에서만 지정한다.

## D-031 · 2026-10-01 · 곡 타일 메뉴
- 곡 줄의 ⋮ · 길게 누르기 · 데스크톱 오른쪽 클릭은 모두 `showTrackMenu` 하나를 연다. 모양은 재생목록 설정 메뉴와 같은 바텀 시트(D-025). 항목을 고르면 시트가 값(enum)만 돌려주고 이어지는 대화상자 · 안내는 곡 줄 쪽 `context`에서 처리한다 (시트가 닫힌 뒤에도 안전하게).
- 이번에 넣은 항목: 다음에 재생 · 대기열에 추가 · 재생목록에 추가 · 정보 편집 · 커버 이미지 설정 · 삭제. 가사 설정 · 파일 위치 보기 · 커버의 웹 검색은 각각 별도 상세 기능이라 그 기능을 만들 때 항목을 더한다 (동작하지 않는 항목은 두지 않는다).
- 재생목록에 추가: 재생목록 담기는 (재생목록, 곡) 쌍이 유일해 같은 곡이 두 번 들어갈 수 없다. 명세의 "중복 추가 여부 확인"은 이미 들어 있는 곳을 조용히 건너뛰는 것으로 처리한다.
- 정보 편집은 제목 · 아티스트 · 앨범 · 장르만. 제목은 필수(앞뒤 공백 제거 후 비면 저장 안 함), 나머지는 비워서 "알 수 없음"으로 되돌릴 수 있다. 기기에서 다시 불러와도(uri가 같음) 고친 값은 유지한다. 음원 파일의 태그는 건드리지 않는다.
- 삭제는 **보관함 기록 + 재생목록 담김 + 재생 기록 + 커버**만 지우고 음원 파일은 지우지 않는다. 파일 삭제는 되돌릴 수 없고 Android 저장소 권한 문제가 있어 따로 정한다. 지운 곡은 재생 대기열에서도 뺀다.
- 곡은 `id`로만 같다고 본다(`Track.==`). 그래서 곡 정보를 고쳐도 목록이 "그대로"로 비교되는 문제가 있어, 보관함 · 홈 상태에는 `revision`을 두어 새로 받을 때마다 다르게 만든다.

## D-032 · 2026-10-01 · 로컬 가사
- 범위: FD-53의 로컬 부분(직접 입력 · 파일 선택 · 저장 · 플레이어 표시). 웹 가져오기와 LRCLIB 검색은 따로 한다.
- 저장은 앱 폴더 `lyrics/<곡 id>.lrc|.txt` + DB(`lyrics_files`). 싱크 여부는 글에 `[mm:ss.xx]`가 하나라도 있는지로 정하고, 확장자는 그에 맞춘다. 원문 그대로 저장하며 저장소에는 가사 파일을 넣지 않는다.
- 읽는 순서: **직접 저장한 가사 → 음원 옆 같은 이름 `.lrc` → 파일 태그 속 가사**. (명세 "옆 .lrc를 먼저"는 LRCLIB보다 먼저라는 뜻으로 보고, 사용자가 직접 고른 것을 가장 앞에 둔다.) 옆 파일은 재생 주소가 파일 경로일 때만 본다.
- 태그 가사는 `audio_metadata_reader`로 읽는다. 저장하지 않고 열 때마다 읽으며, 읽기 실패 · 미지원 형식은 모두 "가사 없음". Android `content://`는 `LyricsChannel.copyToCache`로 캐시에 복사해 읽고 지운다.
- 비워서 저장 = 가사 삭제. 곡을 삭제하면 가사도 지운다.
- 플레이어는 커버 ↔ 가사 전환. 싱크 가사는 재생 위치 줄 강조 + 줄 누르면 이동.

## D-033 · 2026-10-01 · 공통 UI 피드백 (카드 줄이기 · 팝업 메뉴 · 파일 삭제)
- **카드는 보관함 · 재생목록에만** 쓴다. 홈(오늘 · 통계 · 빈 상태), 검색(재생목록 헤더 · URL 결과 · 빈 상태), 보관함 빈 상태, 설정 묶음(`SectionCard`)은 카드 면(유리 · 테두리)을 없애고 제목 · 본문 · 구분선으로 보여 준다. 테마 미리보기 화면은 보관함 · 재생목록 카드 샘플만 둔다.
- 미니 플레이어는 가로 전체 너비, 모서리 반경 없음 (바깥 여백 제거).
- 테마 미리보기는 설정 › 테마의 한 줄(`ThemePreviewScreen`)로 열리는 **별도 화면**. D-030의 "테마 카드 맨 위 미리보기"를 바꾼다. 최상위 내비게이터에서 열어 하단 탭 · 미니 플레이어를 가린다.
- PIN 화면(`PinEntryScreen.open`)도 최상위 내비게이터에서 열어 하단 탭 · 미니 플레이어를 가린다.
- 곡 메뉴는 바텀 시트 대신 **팝업 메뉴**(`showAppMenu`)로 바꿨다 (D-031 갱신). ⋮ 버튼은 버튼 옆에, 길게 누르기 · 오른쪽 클릭은 눌린 자리에 뜬다. 재생목록 설정 메뉴(D-025)도 D-034에서 팝업 메뉴로 바꿨다.
- 커버 이미지는 **곡 타일 팝업 메뉴에서만** 바꾼다. 전체 화면 플레이어 커버의 편집 버튼 · 누르기는 없앴다.
- **삭제는 음악 파일까지 지운다** (D-031의 "파일은 지우지 않는다"를 바꾼다). `DeleteTrack`: 파일 먼저 지우고(`TrackFileRepository`), 성공해야 보관함 · 재생목록 · 기록 · 커버 · 가사를 정리한다. 파일을 못 지우면(권한 거절 · 삭제 동의 취소) 기록은 그대로 두고 안내한다. 이미 없는 파일은 지운 것으로 본다. 곡 메뉴의 삭제 확인 문구에 "되돌릴 수 없다"를 적는다.
  - Android `content://`는 `MediaStoreChannel.deleteAudio`: 먼저 바로 지워 보고, 앱이 만든 파일이 아니면 Android 11+는 `MediaStore.createDeleteRequest`, Android 10은 `RecoverableSecurityException`의 동의 창을 띄운다. Android 9 이하는 `WRITE_EXTERNAL_STORAGE`(maxSdk 28)로 직접 지운다. 데스크톱은 파일 경로를 `File.delete`.
- **재생목록 안의 곡 메뉴**는 삭제가 "재생목록에서 빼기"(`PlaylistRepository.removeTrack`, 보관함 · 파일은 그대로)와 "파일 삭제"로 나뉜다. `showTrackMenu(..., playlistId:)` · `TrackMoreButton(playlistId:)`로 켠다. 재생목록 상세(곡 목록) 화면이 아직 없어 이 변형을 부르는 화면은 아직 없다 — 상세 화면을 만들 때 `playlistId`를 넘기면 된다.

## D-034 · 2026-10-01 · 재생목록 피드백 (대표곡 · 팝업 메뉴 · 상세 · 좋아요)
- **카드는 얇은 테두리 안에 커버 · 이름 · 곡 수 · 구분선 · 대표곡 칸**으로 구분한다 (반경 12, 커버 위 글자 · 안쪽 카드 없음, 대표곡 칸은 접으면 이름 · 가수 한 줄, 누르면 아래에 한 줄(작은 커버 이미지 · 장르 · 재생 버튼)이 더 생기고 위의 제목 · 가수는 그대로이며, 재생 버튼으로 그 곡을 바로 재생해 미리 듣는다. 펼침 상태는 앱을 켜 둔 동안 유지). 대표곡은 한 곡만 보여 준다 (이전: 많이 들은 곡 3개 / 아티스트). 대표곡 = 이 재생목록에서 가장 많이 들은 곡, 들은 기록이 없으면 가장 먼저 담은 곡 (`Playlist.featured`). `topTracks` · `topArtists`는 없앴다.
- **재생목록 메뉴는 팝업 메뉴**(`showPlaylistMenu`, D-033의 "재생목록 설정 메뉴는 시트"를 바꾼다). 카드의 ⋮ · 길게 누르기 · 오른쪽 클릭 · 상세 화면의 ⋮가 같은 메뉴를 연다.
  - 항목: 전체 재생 · 카드 색(하위 팝업: 색 견본 아이콘 + 이름, 고른 것은 체크) · 이미지(별도 팝업: 사진에서 고르기 / 기본 이미지로) · 이름 바꾸기 · 삭제(확인 대화상자, 곡은 보관함에 남음).
