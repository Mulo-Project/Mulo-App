# 검색 · 상세 화면 로딩 단축 (2026-11-10)

## 병목 (코드 기준, 기기 실측 전)
- 키워드 검색: yt-dlp `ytsearchN:` (폰에서 수 초). 다음 쪽을 부를 때마다 `(page+1)*size`개를 처음부터 다시 받아서 쪽이 갈수록 느려진다.
- 상세 화면: 곡 정보(yt-dlp)와 채널 정보(yt-dlp)가 `_ExecGate`(한 번에 하나) 줄에 서서 차례로 돈다 → 채널 이미지 · 구독자 수는 곡 정보 + 채널 시간을 합친 만큼 늦게 뜬다. 미리 듣기 주소 읽기가 yt-dlp로 넘어가면 그 뒤로도 밀린다.

## 변경
- `YoutubeExplodeEngine.search`: 유튜브 · 최신순 아님이면 youtube_explode_dart로 읽는다. 같은 검색어는 다음 쪽을 앞 결과 뒤에서 이어 읽는다(최근 3개 검색 기억). 최신순 · 다른 사이트 · 실패(10초 제한)는 안쪽 엔진.
- `YoutubeExplodeEngine.fetchChannel`: `/channel/…` · `/@…` · `/user/…` 주소는 라이브러리가 읽는다(10초 제한). 못 읽으면 안쪽 엔진.
- `fetchInfo`(곡 정보)는 그대로: 자막 언어 · 공동 작업자 · 분류 · 앨범이 라이브러리에 없다.
- 로그: `[MuloSearch] explode 검색 …ms`, `explode 채널 …ms`.
- 패키지 · Manifest 변경 없음.

## 한계 / 후속
- 라이브러리 검색 결과에는 올린 날이 없고(상대 표기뿐) 설명은 앞부분이다.
- 곡 정보도 줄일 여지: 라이브러리 `videos.get`로 먼저 채우고 yt-dlp는 나머지를 뒤에서 채우기(인터페이스 추가 필요). 기기 로그를 보고 결정.

## 확인 필요
- PC: `dart format`, `flutter analyze`, `flutter test` (이 환경에서는 컴파일하지 못했다).
- 기기: 검색 첫 쪽 · 다음 쪽 시간(`explode 검색` 로그), 상세 화면에서 채널 이미지가 뜨는 시간, 한글 검색어 결과가 이전과 비슷한지.
