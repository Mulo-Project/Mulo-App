## 불러오는 폴더 빼기
- 빼기 전에 확인창(사라질 곡 수 · 파일은 안 지워짐)을 띄운다. 설정의 폴더 시트와 저장 위치 대화상자가 같은 확인창을 쓴다 (`confirmRemoveLoadedFolder`).
- 저장 위치 대화상자에도 폴더 빼기(×) 추가. 기본 위치 · 지금 위치 · 목록에 없는 위치는 뺄 수 없다.
- 폴더를 빼면 그 폴더에서 불러온 곡도 보관함에서 지운다 (`RemoveLoadedFolder`가 보관함 DB 행만 지움, 파일은 그대로). 남은 폴더 안에 겹치는 곡은 남긴다. 전에는 목록만 줄고 곡이 그대로 남았다.
- 폴더를 빼서 보관함에서 지워진 곡은 재생 대기열에서도 뺀다 (`NowPlayingCubit.removeFromQueueByIds`). 재생 중이던 곡이면 다음 곡으로 넘어간다. `RemoveLoadedFolder`는 지운 곡 id를 돌려준다.
- 저장 위치 고르기를 대화상자에서 바텀 시트로 통일 (`save_folder_sheet.dart`, `showSaveFolderSheet`). 폴더 시트와 같은 모양이고, 닫을 때는 시트 밖을 누르거나 내린다 (취소 버튼 없음).
- 저장 위치 목록을 불러오는 폴더와 따로 저장한다 (`library.saveLocations`, `SaveLocationsCubit`). 불러오는 폴더를 더하면 저장 위치에도 더해지지만, 그 뒤로는 한쪽을 빼도 다른 쪽은 그대로다. 저장 위치를 뺀다고 불러오는 폴더 · 곡이 지워지지 않고, 불러오는 폴더를 빼도 저장 위치는 남는다. 직접 고른 폴더는 저장 위치 목록에 더한다. 처음 쓸 때(저장한 적 없음)는 기존 불러오는 폴더 목록으로 시작한다. 저장 위치 시트의 × 에는 확인창이 없다.
- 받을 때 재생목록 고르기도 대화상자에서 바텀 시트로 통일 (`playlist_picker_sheet.dart`, `showPlaylistPickerSheet`). 목록 · 새 재생목록 입력(키보드 위로 올라옴) · 선택 완료 버튼, 밖을 누르거나 내리면 변경 없이 닫힘.
- 검색(받기) 정렬에도 오름 · 내림차순 알약 적용: 인기 · 길이 · 제목에 방향 화살표 (기본: 인기 많은 순, 길이 짧은 순, 제목 가나다순). 관련도 · 최신순은 찾는 쪽이 정한 순서라 화살표가 없다. "짧은 순 / 긴 순"은 "길이순" 하나로 합쳤다. 기준을 바꾸면 기본 방향으로 돌아간다.
- 정렬 알약(`AppDropdown`)의 화살표 · 펼침 아이콘을 `iconSm`으로 줄이고 앞 아이콘 간격도 좁혔다.
- 재생목록 가져오기 화면 정리: 찾은 재생목록을 열어 보는 동안(읽는 중 · 곡 목록 · 실패) 위 막대 뒤로 가기 · 시스템 뒤로 가기가 찾은 목록으로 돌아가고(`PopScope`), 읽는 중에는 "검색 결과로" 버튼을 보인다. 열어 보는 동안은 찾기 칸 · "내 재생목록" 버튼을 숨긴다. 곡 목록 머리는 대표 이미지(72) · 이름 · 곡 수, 구분선, "N/M곡 선택됨" + 전체 선택 한 줄로 바꾸고 따로 있던 "검색 결과" 글자 버튼은 없앴다. 실기기에서 느린 읽기를 직접 확인하지는 못했고, 읽는 중 취소를 다루는 위젯 테스트는 추가하지 못했다 (cubit의 backToResults 테스트는 기존).
- 재생목록 카드 순서 바꾸기를 별도 목록 화면(`playlist_reorder_screen.dart`, 라우트 `/playlists/reorder`, 위 막대 버튼)에서 재생목록 탭 격자 안으로 옮겼다. 카드를 길게 누르면 그 자리에서 끌려 올라오고(`LongPressDraggable`), 끄는 동안 다른 카드가 비켜 주며(`DragTarget`), 놓으면 저장된다. 화면 위아래 가장자리에서는 목록이 스크롤된다. 좋아요 목록은 끌 수 없고 맨 앞 자리로도 못 간다. 카드 메뉴는 ⋮ · 오른쪽 클릭(좋아요 카드는 길게 누르기도)으로 연다. `PlaylistGrid(onReorder:)`, `PlaylistCard(longPressMenu:)`.
- 재생목록 가져오기의 "전체 선택"을 체크 토글로: 모두 골랐으면 켜진 체크(강조), 아니면 빈 동그라미. 글자는 늘 "전체 선택".
- 반응 시간 보정 페이지: 구역마다 유리 카드(현재 값 · 박자 테스트 · 곡으로 확인)로 나누고 화면 좌우 여백을 다른 화면과 같은 `AppSpacing.screen`으로, 뒤로 가기는 `AppBackButton`, 곡 확인의 두 버튼은 같은 너비로 나란히, 배경은 `AppBackground`.
- 저장 위치 시트의 폴더 빼기(×)는 설정에서만(`showSaveFolderSheet(removable: true)`). 받기 · 채널 새 영상 저장 위치에서는 고르기만 한다.
- 새 영상 시트: 닫아도 목록이 지워지지 않는다. 위쪽 "비우기"(확인창)를 눌러야 확인한 것으로 표시하고 비운다. 새 영상이 없을 때 체크 아이콘을 보인다.
- 이미지 "웹에서 가져오기" 브라우저(`cover_web_browser.dart`)의 위쪽 검색칸을 없앴다. 웹 페이지(빙 이미지)가 자기 검색창을 주므로 겹쳤다. 처음 검색어(곡 · 앨범 이름)로 열고, 없으면 빙 이미지 첫 화면을 연다.
- 오버레이 가사(Android, `LyricsOverlay.kt`): 메뉴 문구를 "오버레이 가사 켜기/끄기"로. 창을 탭하는 대신 꾹 눌러야 숨기기 · 끄기가 나온다(탭은 메뉴 닫기). 숨기기로 줄어든 칩은 화면 어디로든 끌 수 있고 놓은 자리를 기억한다(`chipX/chipY`, 창의 위 위치 `y`와 따로). 창 맨 아래 손잡이를 아래로 당기면 다음 줄이 최대 8줄까지 늘고, 고른 줄 수를 기억한다. 가볍게: 줄이 바뀔 때만 글을 바꾸는 기존 구조(다음 줄 시간 타이머 하나)를 그대로 두고, 줄 수가 늘어도 글 두 칸(현재 · 다음 묶음)만 갱신한다. `compileLiteDebugKotlin`은 통과했지만 실기기에서 끌기 · 당기기 느낌은 확인하지 못했다. "삭제"는 기존 "끄기" 버튼(설정을 끄고 창을 내림)으로 두었다.
- 보관함(홈 포함)에는 불러오는 폴더(기본 저장 위치 + 추가한 폴더) 안의 곡만 보인다. 받을 때 저장 위치를 불러오는 폴더 밖으로 정하면 그 곡은 기록(DB · 재생목록 · "이미 받은 곡")에는 남지만 보관함에는 안 나타나고, 그 폴더를 불러오는 폴더로 더하면 나타난다. 폴더를 모르는 곡은 그대로 보인다. `WatchLibraryTracks`가 거르고(`isVisibleInLibrary`), 불러오는 폴더가 바뀌면(`LoadedFolderRepository.watchChanges`) 다시 거른다. 재생목록 상세는 재생목록에 담긴 곡을 그대로 보여 준다.
- 검색 시간 제한: 서버 엔진은 연결 10초 · 응답 60초 제한이 이미 있었다. 데스크톱 로컬 엔진(yt-dlp 실행)과 youtube_explode 재생목록 검색에는 제한이 없어 응답이 없으면 끝없이 돌았다. 로컬은 한 번 실행이 60초를 넘으면 프로세스를 끊고 연결 실패(다시 시도 화면)로, 재생목록 검색 대체 경로는 30초로 제한했다. Android는 서버 엔진(lite) 또는 내장 yt-dlp 경로라 이 변경 대상이 아니며, 내장 yt-dlp의 시간 제한은 확인하지 못했다.
- 가사 설정 · 싱크 설정으로 저장한 가사를 앱 저장본과 함께 음원 파일의 가사 태그에도 쓴다(`TrackTagRepository.writeLyrics`, `SaveLyrics`가 호출). 받을 때 가사를 넣는 것과 같은 쓰기 경로(mp3 · m4a는 라이브러리, opus 등은 ffmpeg full 빌드)이고 곡 정보 태그 쓰기처럼 못 쓰는 파일(권한 없음 · 형식 · 파일 없음)은 조용히 건너뛴다(앱 저장본은 그대로 쓰인다). 가사를 비워 지울 때는 파일 태그를 지우지 않는다. 이미 저장해 둔 가사를 한꺼번에 파일에 옮기는 이관은 하지 않았다(가사를 다시 저장할 때 써진다).
- 오버레이 가사 늘리기 개선(`LyricsOverlay.kt`): 맨 아래 손잡이를 당기면 창 높이가 연속으로 늘어 화면의 80%까지 커지고(줄 수가 아니라 높이를 기억, `expandPx`), 늘린 모양에서는 현재 줄이 가운데에 오고 위에는 지나간 줄, 아래에는 곧 나올 줄이 현재 줄에서 멀수록 흐리게 보인다. 위 · 아래 각 12줄 칸을 미리 만들어 두고 높이만큼만 보이게(넘치는 쪽은 잘림). 150dp보다 낮게 당기면 원래 모양(현재 줄 + 다음 한 줄)으로 돌아가고, 화면 아래로 넘치면 창을 위로 올린다. `compileLiteDebugKotlin`은 통과했지만 실기기에서 당길 때의 느낌은 확인하지 못했다.
- 추가일순 정렬: 기기에서 불러온 곡의 추가일이 "찾은 시각"이라 한 번에 찾은 곡은 모두 같은 날짜였다. 이제 파일 날짜를 쓴다: Android는 MediaStore `DATE_ADDED`(기기에 들어온 시각), 데스크톱은 파일 수정 시각(받은 파일이면 받은 날짜). 이미 보관함에 있는 기기 곡도 다시 찾을 때(앱을 켤 때 · 폴더 추가 · 보관함 다시 찾기) 파일 날짜로 고쳐진다. 앱에서 받은 곡은 받은 시각 그대로. 실기기에서는 확인하지 못했다.
- 불러오는 폴더를 더하면 곡 정보와 이미지를 제대로 읽어 오도록: 전에는 폴더를 더해도 곡 목록만 찾고(MediaStore의 제목 등) 파일 태그 읽기 · 내장 이미지 가져오기는 보관함 화면의 "다시 찾기"에서만 돌아서 이미지가 비어 있었다. 이제 폴더를 더하거나 뺀 뒤에도 같은 순서(곡 찾기 → 파일 태그 읽기 → 내장 이미지 가져오기)로 채운다 (`LoadedFoldersCubit`, `RestoreFromFileTags.run` · `FillEmbeddedCovers.run`에 진행 콜백). 폴더 시트에는 단계 이름과 끝낸 수 / 전체, 진행 막대를 보이고, 이미지가 붙으면 커버 목록을 다시 읽는다.
- 불러오는 폴더를 뺄 때는 곡을 다시 찾지 않는다(뺀 폴더의 곡은 이미 보관함에서 지웠고 남은 폴더는 그대로). 진행 문구도 "폴더를 빼고 보관함을 정리하는 중이에요"로 따로 둔다 (`LoadStage.removing`). 전에는 뺄 때도 "폴더에서 곡을 찾는 중"이라고 떴다.
- 오버레이 가사 줄 간격: 늘린 창에서 위 · 아래 줄 사이가 손잡이를 당기는 만큼 함께 벌어진다(늘리지 않으면 4dp, 최대로 늘리면 16dp, `applyGap`). 컴파일만 확인했고 기기에서 보이는 정도는 확인하지 못했다.
- 오버레이 가사 가로 화면: 창 너비를 화면 너비에서 좌우 16dp를 뺀 만큼, 최대 560dp까지만 두고(가운데 정렬) 화면이 돌아가면 다시 맞춘다. 창이 화면 아래로 넘치면 위로 올리고, 늘린 높이는 화면 높이의 80%라 가로 화면에서는 자연히 낮아진다. 칩은 이미 화면 안으로 끼워 넣는다. 컴파일만 확인했고 기기에서 돌려 보지는 못했다.
- 오버레이 가사: 다음 곡에 싱크 가사가 없으면 창을 내리지 않고 "가사가 없어요"(일반 가사만 있으면 "싱크된 가사가 없어요")만 보여 준다. 꺼져 있거나 곡 정보 숨기기일 때만 내린다. Dart `LyricsOverlayCubit.sync(emptyLabel:)` → 네이티브 `show`의 `emptyLabel`, 줄이 없으면 타이머 없이 글만 띄운다. 컴파일 · Dart 테스트만 확인했고 기기에서는 확인하지 못했다.
- 오버레이 가사: (1) 글이 길어지거나 메뉴 · 늘림으로 창 크기가 바뀌면 그때마다 화면 아래로 넘치는지 보고 위로 올린다(창 크기 변화에 맞춘 레이아웃 리스너). 전에는 늘릴 때 · 모양을 바꿀 때만 계산해서 줄이 길어지면 아래가 가려질 수 있었다. (2) 숨기기 칩은 놓으면 가까운 왼쪽 · 오른쪽 가장자리로 160ms 동안 미끄러져 붙는다(위아래 위치는 놓은 곳). 움직이는 동안에만 그리고 끝나면 도는 것이 없어 발열 영향은 무시할 수준이다. 컴파일만 확인했다.
- 새 영상 안내: 목록은 "비우기"를 누를 때만 지워지고, 앱을 켤 때 뜨는 안내 줄은 한 번 안내했거나 새 영상 화면에서 본 영상을 다시 세지 않는다. 본 영상 id를 따로 기록한다(`SubscriptionRepository.loadSeenVideos`/`saveSeenVideos`, 최근 500개). 안내 줄의 "보기"를 누르거나 새 영상 화면을 닫으면 지금 보이는 영상이 기록되고(`NewVideosCubit.acknowledge`), 다음 실행에서 새로 올라온 영상이 있을 때만 안내한다. 안내 줄이 그냥 사라지기만 했으면(안 눌렀으면) 다음 실행에서 다시 안내한다. 알림(백그라운드 확인)은 이 변경 대상이 아니다.
- 오버레이 가사: 늘린 창에서 지나간 줄이 없으면(곡 처음 · 가사 없음) 윗칸을 접어 현재 줄이 가운데로 내려가지 않고 맨 위에 붙는다. 컴파일만 확인했다.
